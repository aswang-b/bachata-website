# src/components Context

> Tier 2 — referenced from [docs-overview.md](../../docs/ai-context/docs-overview.md). Shared Astro components used across public pages.

## Purpose

Reusable UI pieces included by pages in `src/pages/`. All are `.astro` components; interactivity (where present) is plain DOM script in an inline `<script>` block, not a framework component — this project has no React/Vue/Svelte components.

## Key Files

| `Header.astro` | Sticky site nav; nav items can be hidden per `siteSettings` keys (`hide_about_nav`, etc.; read from `Astro.locals.siteSettings`, which middleware.ts loads alongside the time zone); highlights the admin page differently. The Register for Classes / Events buttons stay in the header row at every width (switching to short "Classes"/"Events" labels when space runs out), so the phone menu doesn't repeat them. On a phone the register buttons and the admins' inbox share one height (32px) and corner. Inside the installed app it shows just the switch. A dot on the bell until it's opened once or notifications are on. On Android in Chrome (the browser that installs a real app), each page sets or clears a Cache Storage flag (`/__dwb/installed-app`: open as the app, or `getInstalledRelatedApps` via the manifest's `related_applications`); The flag holds when it last saw the app installed; `sw.js` leaves out the notification's logo picture while it's under 30 days old, since the phone already shows the app's icon (after that the app may have been removed, so the logo is back; `tests/unit/serviceWorker.test.ts`). ## Integration Points

- **Depends on**: `src/lib/previewMode.ts` (PreviewBanner), `/api/banner` (AnnouncementBanner), `src/assets/highlights/` (DanceHighlights), `src/lib/siteSettings.ts` read while the page renders, so the header arrives whole with no buttons popping in after load (Header)
- **Used by**: `BaseLayout.astro` (Header, Footer, banners globally); `register.astro`, `contact.astro`, `check-in.astro` (IntakeForm); `IntakeForm.astro` (ClassCalendarPicker)
- **Pressed look**: one rule set at the end of `src/styles/global.css` dims any link/button/summary/`role=button` while pressed, and scales buttons and rounded links to 0.98 (flyers `data-flyer-open` dim only; opt out with `data-no-press`; reduced motion: no scale). Don't add per-component `active:` classes.
- **Sending state**: the sign-up, contact and check-in forms call `trackSubmit(form, label)` (`src/scripts/submitState.ts`) last in their script: a submit that goes through locks the button (`aria-busy`, width kept, "Registering…" / "Sending…" / "Checking in…") and a second one is refused; `pageshow` (back button, bfcache) unlocks it. Don't set the button's `disabled` in a form's own code (`codebaseRules`)
- **Tap targets**: `hit-44` (with `relative`) in `global.css` gives a small control a 44px tap area on touch screens without changing its look; the header bell and menu button have their own rules there (the bell is 40px wide: its neighbours are 8px away)

## Architecture

`IntakeForm` is the shared skeleton for every "collect visitor info" flow (registration, contact, check-in); pages differentiate behavior purely through props rather than separate form components, so changes to shared field markup/validation belong here rather than being duplicated per page.
